# 项目原则

这份文档沉淀项目早期最稳定的判断标准：Agent-first 协作方式、产品取舍和界面设计原则。它用于帮助人和 Agent 在信息不完整时做出一致决策。

## Agent-First 工作原则

- 人来定方向，Agent 负责执行和推进。
- 仓库内可追溯的知识，比私有上下文更重要。
- Agent 反复失败时，优先修脚手架和环境，不是继续加 prompt 压力。
- 短而稳定的入口文档，比越来越长的大 prompt 更可靠。
- 能变成机械检查的约束，就不要只停留在口头规范。
- 速度很重要，但无节制地堆积熵会迅速拖垮效率，所以要持续整理和收口。

## 产品判断

- 先明确核心用户和主要使用场景，再选择实现范围。
- 优先交付真正能降低协作成本、减少重复解释、提升可验证性的能力。
- 当前阶段默认更看重可信度、可维护性和 Agent 可执行性，其次才是功能覆盖面。
- 早期交付可以轻量，但必须有清楚目标、非目标和验收方式。
- 进入成熟运营后，判断标准应逐步转向稳定性、可观测性、安全边界和长期维护成本。

## 设计原则

- 界面和交互应服务真实工作流，不为了展示感堆复杂装饰。
- 视觉系统、字体、颜色、间距和组件选择要优先复用已有前端约定。
- 共享组件适合承载稳定、跨页面复用的模式；一次性页面特化逻辑留在应用侧。
- 新增界面能力时，同步考虑无障碍、响应式、错误状态和本地验证路径。
- 设计文档应写清当前状态和简短摘要，并关联引入它的需求、plan 或 history。
